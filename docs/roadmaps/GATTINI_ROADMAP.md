## How to execute

Read the master plan, then execute the earliest ready task on the critical path while running independent, bounded preparation in parallel. A task is ready for integration only when its listed dependencies and any preceding human checkpoint are satisfied. Parallel preparation does not mark a later task complete or authorise its live checks. Mark a task complete only after the coordinating agent has inspected the combined change and recorded commands, outcomes, and evidence. Split work larger than a focused session into non-overlapping deliverables. Checkpoints require human review. Future expansion milestones require a fresh detailed plan before coding.

Use three release gates: A = useful OpenCode delegation; B = verified runtime neutrality; C = installable/editor-friendly. Browser/desktop/remote expansion follows separately.

### Asynchronous execution plan

Keep one coordinating agent responsible for the dependency graph, shared contracts, integration, verification, and roadmap evidence. Dispatch workers only for independent deliverables with an explicit file or worktree owner, model and reasoning effort, allowed actions, tests, and completion condition. Read-only discovery may share a checkout. Concurrent edits need disjoint paths and one writer per interface or database schema; use separate worktrees when they can start from an accurate baseline. The previously uncommitted Tasks 8–12 project work was committed as `76dc599`; the unrelated image remains untracked. Inspect the actual state before moving work between checkouts. The coordinator reviews each result, integrates it in dependency order, and runs the combined checks. Workers do not recursively delegate or approve their own work. A failed or unavailable worker does not count as evidence.
