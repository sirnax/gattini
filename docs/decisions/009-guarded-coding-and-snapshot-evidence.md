Status: Task 9 complete and Checkpoint 3 accepted on 26 September 2026, with the limits below. The durable read-only proposal path was tested offline; the original direct-edit coding launch remains blocked after a symlink write escape was observed. A narrower proposal/apply path passed adversarial fixtures and one approved disposable real code task before daemon integration.

## Decision

The explicit trusted-local code request names a repository, full base commit, task, and direct-argv verification commands. It requires a separate exact launch approval. The job store records the proposal before `WorktreeManager` prepares a job-owned branch and worktree; the approval binds the worktree path, base, commands, task, agent, and model. The user's dirty source checkout is excluded. A failed or uncertain owned worktree is retained for inspection.

The original direct-edit adapter's proposed rules deny all tools, then allow read/glob/grep and `edit` while keeping `external_directory` denied. The [published V2 permissions reference](https://opencode.ai/v2/docs/permissions) says `edit` covers edit/write/patch, internal paths are location-relative, and external paths require a separate directory approval. Shell and network tools remain denied. **A controlled probe on installed OpenCode V2.0.18 showed that an in-tree symlink allowed an edit to write outside the worktree.** That adapter's preflight stays disabled. The new daemon route accepts only a read-only V2.0.18 proposal agent with an effective deny-all/read/glob/grep tail, then Gattini validates and applies the patch itself after another approval. A worktree is change separation and offers no host containment; same-user processes still have broader host reach.

The offline snapshot verifier captures a hash of non-`.git` worktree entries, modes, and bytes, hashes the base diff plus untracked content, runs each approved argv directly in the worktree with a timeout and bounded logs, then captures the tree again. Acceptance passes only when at least one command exits zero, all checks pass, and the tree digest is unchanged. A failed check, timeout, or mutation yields failed acceptance independent of worker text. Snapshot capture is capped at 32 MiB and logs at 16 KiB per stream. Checks run in owned POSIX process groups: timeout kills ordinary descendants; background survivors after parent exit cause failed acceptance and group termination. A 250 ms output-drain bound prevents inherited pipes from hanging completion. This does not contain descendants that create new sessions. The structured result retains execution and acceptance separately.

The digest excludes Git metadata; concurrent mutation during capture and later changes to the mutable worktree remain possible. This is evidence over an observed snapshot, not an immutable filesystem or security boundary. Code-session crash reconciliation remains conservative and requires manual inspection rather than replay.

## Narrow offline proposal/apply decision

OpenCode may provide a **read-only text proposal**, but its `edit` tool cannot hold write authority for this path. Gattini accepts a strict JSON patch with exactly `path`, `beforeSha256`, and `afterBase64`. The current validator permits only one existing, tracked, root-level regular file with one link whose status matches the approved base. It rejects absolute paths, traversal, nested paths, symlink targets, hard links, file creation, mode changes, and extra fields. Root-level restriction removes the parent-symlink traversal that escaped the OpenCode tool policy. The validator records the root and target identities, file timestamps, and exact preimage bytes. Write authority is a single-use in-process handle with private copied replacement bytes; a fabricated or copied object cannot call apply. Apply writes a same-directory temporary file, explicitly preserves the target mode independently of umask, then repeats the identity/preimage checks before a single atomic rename. Rejection before rename leaves the target intact; failed staging removes the temporary file. A read-only OpenCode session's text cannot itself call this apply function.

Git inspection uses literal paths and an environment with inherited `GIT_*` overrides removed. Per-command configuration disables fsmonitor, hooks, and configured clean/smudge/process filters; diff also disables external diff and text conversion. These overrides do not edit repository or user configuration. Adversarial fixtures demonstrated that ordinary `git diff` and `git status` otherwise executed a configured clean filter, and diff executed configured text conversion while capturing evidence. The new tree/diff digest format has a `v2` domain prefix and includes modes and file sizes. Historical live evidence below retains its original digest format and has not been rewritten.

`src/cli/gattini-apply-patch.ts` is an independent offline entry point. It requires a ready `WorktreeManager` ownership record, applies one validated proposal, and runs the approved direct-argv snapshot checks. The daemon routes `--trusted-local-code` through a separate read-only proposal and two approvals. The owner accepted Checkpoint 3 with the documented limits.

The boundary is intentionally narrow. It does not support nested code files or multiple-file changes. It assumes no hostile same-user process races the final pre-rename check or replaces the owned root; the project already excludes same-user hostile processes from its security boundary. It does not contain a read-only runtime's host reads, plugins, or provider access. Verification commands can execute code and access the host, and snapshot evidence does not freeze the worktree permanently. The manual offline entry point is not the durable daemon coding flow or an approval mechanism.

The earlier smoke/adversarial run passed 82 tests on Node 24 and 26, plus five repetitions of the five subprocess regressions. The subsequent durable integration and retained snapshot update are described below. Ordinary process-group cleanup is supported on POSIX; verification fails without launching a check on Windows. Detached descendants that escape the group remain outside the containment claim, even though retained pipes cause bounded failed verification.

## Durable proposal and retained evidence update

The daemon's opt-in trusted coding route now uses the narrow proposal path. The first approval binds repository and full base commit, owned worktree, task, exact agent/model/service, read-only V2.0.18 policy and direct-argv checks. The daemon claims an attempt before launch, persists the exact session ID from the event stream, verifies exact session identity and outcome, compares worktree fingerprints before and after the read-only proposal, and validates the strict JSON patch. It then records a second approval for the exact attempt, session, policy, worktree fingerprint, patch path, preimage/replacement hashes and proposal digest. Approval survives restart. Apply rechecks the full worktree fingerprint and patch preimage before one atomic rename. The direct-edit adapter's `CODE_PATH_PERMISSION_SYNTAX_VERIFIED` remains false.

Before launching checks, the verifier writes a bounded private `snapshot.json` containing each non-Git entry's type, mode, path and exact bytes or link target, plus a `diff.patch` for the Git diff. The result records SHA-256 hashes of both files, the v2 tree/diff digests, argv, cwd, exit code, bounded logs and acceptance. Result retrieval rechecks both artifact hashes; missing or altered files return `EVIDENCE_INVALID`. Verification fails if the tree changes while checks run. The patch result is accepted only if the retained file bytes match the approved replacement hash. The artifact holds a copy of observed bytes; filesystem permissions and digests detect ordinary later changes, but this is not a tamper-proof storage service against the same user.

Unclaimed queued launches and approved applies resume after restart. A claimed launch without a handle, a claimed launch with a handle, or a claimed apply/verification becomes `interrupted` and is never blindly replayed. Process-kill tests exercise launch on both sides of handle persistence and verification after apply; store restart fixtures cover the claimed apply phase. Cancellation before launch is terminal; cancellation after apply begins aborts local verification and leaves the job interrupted because the atomic replacement may already have happened. The owned worktree and artifacts remain for inspection. The final offline suites passed 90/90 on Node 24.21.0 and 26.10.0. Offline daemon tests use a fake OpenCode executable; no second paid model run was made. The earlier real-code worktree was rechecked offline with the same direct-argv test, and its v2 snapshot content and diff are retained at the paths recorded in the roadmap.
