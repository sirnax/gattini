# Gattini VS Code client (Task 17)

This local extension requires Gattini daemon release `0.2.0` and protocol v2. It uses `GATTINI_STATE_DIR/gattinid.sock` when that variable is set. Otherwise the socket is under `~/Library/Application Support/Gattini` on macOS, or `$XDG_STATE_HOME/gattini` (default `~/.local/state/gattini`) on Linux. Start the daemon separately. Opening a workspace does not submit a task.

Use **Gattini: Submit Task** in a trusted workspace. With multiple folders, choose one explicitly. The chosen folder labels the local job record; the daemon remains responsible for runtime selection and working directory. The command sends task text with a persisted idempotency key and saves the returned job ID in VS Code workspace state. **Gattini: Show Jobs** opens a plain-text output channel with durable status and bounded event pages. The client polls every three seconds, saves each processed event cursor, and resumes that job after VS Code or daemon restart. A cursor gap or protocol mismatch is shown as an error and never skipped silently.

Use **Gattini: Attach Existing Job** to inspect an exact job ID created by the CLI or another client. It requires Workspace Trust, asks which folder to associate with the job, verifies the ID with daemon status, then saves it locally and refreshes. Attaching never launches a provider or changes the daemon job. Attaching the same job again keeps its event cursor and a single local entry.

**Gattini: Show Result** displays a narrow result projection as text. **Gattini: Show Evidence** requests a verified bounded diff or snapshot metadata projection from the daemon; the extension never reads artifact paths. **Gattini: Approve Pending Action** and **Gattini: Deny Pending Action** select an exact pending approval ID, refresh its row and job state, and ask for confirmation. **Gattini: Cancel Job** selects an exact saved job ID and refreshes durable status after the request. A cancellation request is not proof of runtime termination. Mutating commands require Workspace Trust. There is no webview, HTML interpolation, or diagnostic export.

For local development, run `npm run build --prefix extension` and use VS Code's **Run Extension** action with this folder as the extension development path.

Offline checks use the repository's existing TypeScript installation: `npm run typecheck --prefix extension`, `npm run build --prefix extension`, and `npm test --prefix extension`. Socket fixture tests need permission to create local Unix sockets. The tests include a mocked VS Code API and a real daemon/CLI integration. A disposable VS Code extension-host smoke checked activation and command registration. Manual fake submit/result, exact-ID denial, CLI-job attach/result, and both visible evidence views are recorded in the [local evidence](../docs/roadmaps/TASK17_18_LOCAL_EVIDENCE.md).

Other editors can use the Gattini CLI against the same daemon and durable jobs. This extension has only been tested in VS Code; native compatibility with any derivative editor has not been established.
